## What the project asks

Whether pooling hourly weather data from five cities improves 24-hour temperature
forecasting compared with training on a single city on its own, and whether a
Temporal Fusion Transformer offers any advantage over simpler approaches.

| RQ | Question | Where it is answered |
|----|----------|----------------------|
| RQ1 | Can a TFT outperform an LSTM? | notebooks 15, 16, 17 |
| RQ2 | Do per-city models beat a pooled multi-city model? | notebook 11 |
| RQ3 | Which input variables drive the forecasts? | notebook 18 |
| RQ4 | Can conformal prediction give calibrated intervals? | notebook 8 |

## Headline results

Test set, all five cities, 24-hour horizon, mean absolute error in degrees C.
Every learned model was tuned by its own grid search before comparison.

| Model | MAE | Type |
|-------|-----|------|
| TFT | 1.247 | tuned |
| Gradient boosting | 1.263 | tuned |
| LSTM | 1.266 | tuned |
| Linear regression | 1.575 | baseline |
| Seasonal naive | 2.091 | baseline |
| Climatology | 2.470 | baseline |
| Persistence | 2.935 | baseline |

RQ2: pooled model 1.268 against a per-city mean of 1.272 — effectively identical.

### A note on notebooks without visible outputs

Five notebooks (02, 03, 10, 11, 15) show code but no rendered outputs, because
they were trained on Kaggle or Google Colab GPUs rather than locally. Neither
platform's download returns rendered cell outputs. Each of those notebooks opens
with a note stating where it ran, what it produced and which result file to check.
Notebook 16 independently reloads the saved model checkpoint and reproduces the
headline TFT score, so the result does not rest on an unrendered notebook.

The TFT is not practical to train on CPU — roughly 3.75 hours per epoch on the
full dataset — which is why GPU platforms were used.

## Data

Five cities (Jena, London, New York, Sydney, Tokyo), hourly Open-Meteo records
for 2000–2009. 438,360 raw hourly rows, complete with no missing values.
Published as a Kaggle dataset: `tharun2431/multi-city-weather-2000-2009`.

The processed master file (`master_all_cities.csv`, about 162 MB) is not included
here because of its size. Notebook 01 regenerates it from the raw city CSVs.
